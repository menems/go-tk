# capability-gate
> a service names, per route, the right a caller must hold, and a caller holding it nowhere is refused without the refusal saying which

**Created**: 2026-09-22
**Out of scope**: where a principal's rights come from and how they are stored, fetched or cached, which stays in the predicate the service hands in; roles, groups, hierarchies, wildcards and implied rights; a right over one object rather than over a route, which needs the request's path values and the service's own data; combining several rights under an all-of or any-of operator, a route needing two being wrapped twice; logging or auditing a refusal; what the route table discloses to an anonymous caller, which `route-gate` owns and this plan neither widens nor closes; any right named anywhere but at wiring.
**Approach**: A per-route right wrap in `transport/http` (package `httpd`, root module, stdlib only) beside `RequireBearer`: the service names one right per wrap and hands the predicate that answers whether the principal riding under its own `authctx` key holds it, and the wrap sits on the handler inside the bearer wrap, so the order is the route table, then the bearer, then the right, and nothing is asked about rights for a request nobody routed or nobody authenticated. Not a right named on `Route` nor a gate in front of `NewRouter`, both settled by the two bricks below; and the refusal is an honest 403 naming no right, not the table's own 404 replayed to hide that the route exists, which would close nothing (a covered route's 401 already tells an anonymous caller that route is there, and the table's 404/405 split answers before any credential is read) while costing an operator the difference between a route closed on purpose and one closed by a wiring mistake.
**Threat surface**: input: nothing new is read from the request, the right being named at wiring and the caller coming from the request context where the service's own bearer wrap put it, so a refused request is parsed no further, echoed nowhere and written nowhere. authn/authz: this is a service's authorization boundary, it holds no right table and grants nothing, the verdict belonging to the predicate handed in, so a predicate that answers wrongly authorizes wrongly, and a wrap reached with no principal refuses rather than serving; coverage is exactly the set of handlers wrapped, a route wrapped for no right demanding none; a route named for GET is reached by HEAD too, and the wrap sitting on the handler, that HEAD is checked like the GET; the route table still answers 404 and 405 before any credential is read and a covered route still answers 401 before any right is asked about, so what a caller can learn about the table is exactly what `route-gate` and `bearer-principal` left it. secrets: the refusal is one fixed body under one code, identical whatever right was demanded and whatever the caller holds, naming neither the right missing nor any right held nor the principal, and the predicate's own error text stays out of every answer and is written nowhere here. No egress, the predicate's own calls being the service's. No dependency added, the root module keeping its stdlib-only set.
**Landmarks**: transport/http/: package `httpd`, root module, stdlib only, where this lands, beside the `NewRouter` route table, the `RequireBearer` wrap a covered route already carries and the `WriteError` / `ErrorCode` failure envelope a refusal goes out through; authctx/: the `Key[T]` the principal rides under and is read back from, verifying nothing and naming no transport; health/: the repo's other handler, served through no table and covered by nothing, out of scope; go.mod: the root module, nothing required outside the stdlib; Makefile: `make check` is fmt-check, vet and race over every module; README.md: one H2 per package, its shape and the reason behind it, the `transport/http` one carrying the table, the bearer wrap and the envelope.

## Steps
1. [transport] Demand, per route, a right its caller must hold
   - seam: the handler `NewRouter` returns, over a served request from the package's external test
   - acceptance: a request on a route whose named right its caller holds reaches that route's handler, which still reads the principal back from the request context; the same request from a caller holding that right nowhere is answered 403 in the package's failure envelope, under a machine-readable code of its own, and that handler does not run; that refusal's body and headers are the same for two routes demanding two different rights, name neither the right demanded nor anything the caller does hold, and carry no `WWW-Authenticate` header; a route of the same table demanding no right serves that same caller through its own handler; a request on a path nobody named is still answered 404 and one carrying no credential is still answered 401, nothing being asked about rights in either case

2. [transport] Tell a caller holding nothing from a check answering nothing
   - seam: the same handler `NewRouter` returns, over a served request from the package's external test
   - acceptance: a request whose right check fails instead of answering is answered 500 in that same envelope, under the code the package already writes for a verdict it could not reach, and that route's handler does not run; a request reaching a route that demands a right with no principal in its request context is answered that same 500 and not the 403 a caller holding nothing gets; a client tells the two apart from the status and the code alone, and neither answer carries the principal, the right that was demanded, or anything the check said
