# work-slots
> a service bounds how many costly operations run at once, and a caller finding no place is refused at once instead of waiting

**Created**: 2026-09-23
**Out of scope**: waiting for a place, with or without a deadline, the outcome being a refusal at once; the answer a service gives a caller refused a place, a status, a code or a `Retry-After`, which its handler owns, `httpd` naming none for it; a bound shared across replicas, each process bounding its own hashes as `CountWithin` meters its own calls; a bound per caller or any fairness among callers, which `call-rate` owns in front of the handler; a limiter for operations other than a hasher's, so a general-purpose semaphore package; a default number of places and where that number comes from, a service reading it from its own environment at boot, which `env-values` owns; a context or a cancellation on the `Hasher` interface, which stays as `password-hash` merged it; a ceiling on the cost a stored value carries, which `password-hash` left to the service; logging or counting refusals, as in the merged plans.
**Approach**: A wrapper in `crypto/password` over any `Hasher`, built at wiring with a number of places, answering a new sentinel distinct from `ErrMismatch` and `ErrUnreadable` when every place is held, Hash and Verify drawing on one budget since both spend the same CPU; the in-box hasher and a service's own argon2id one are bounded alike, and nothing already merged changes. Not a general-purpose slots package beside `password`, as `password-hash`'s Approach forecast: under `crypto/` it names a crypto brick that holds nothing crypto, elsewhere it leaves the context the roadmap assigned, and its one caller today is the hasher; not a `NewPBKDF2` option either, which would leave a service's own hasher unbounded.
**Threat surface**: input: the number of places, named by the service at wiring, a number below one refused there under an error naming the value, and a nil hasher refused there too; the plaintext and the stored value pass through to the wrapped hasher unread and unchanged, bounded and parsed as `password-hash` already does. authn/authz: this grants nothing and adds a third refusal, which is non-nil so a login meeting it is denied; a caller folding it into `ErrMismatch` shows an honest user a wrong password under load and feeds any lockout it counts, which is why it is distinct; the bound turns CPU exhaustion into refusals, so a flood of logins, or a few stored values carrying an attacker-written cost, can hold every place and have every honest login refused at once rather than slowed, which a service limits by metering callers in front (`call-rate`) and bounding the rows it stores. secrets: the plaintext crosses the wrapper into the wrapped hasher and nowhere else, the wrapper keeping no copy past the call, and the busy refusal is one fixed error carrying no part of the password nor of the stored value. egress: none. dependencies: none added, stdlib only in the root module.
**Landmarks**: crypto/password/: package `password`, root module, where this lands; crypto/password/hasher.go: the `Hasher` seam and its two refusals, the contract this wraps without changing; crypto/password/pbkdf2.go: the in-box hasher, a seam type handed back over an unexported implementation and a bad value refused at wiring under an error naming it; transport/http/rate.go: `LimitRate` and `CountWithin`, the other brick refusing work at once rather than queueing it, per process.
