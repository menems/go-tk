# call-rate
> a service refuses a caller past its cadence by telling it when to come back, while a caller inside that cadence is served

**Created**: 2026-09-22
**Out of scope**: a shared counter and any implementation of one, so Redis, memcached or a database, with the module and the dependency either would add; where a ceiling and a window come from, a service reading them from its own environment at boot, which `env-values` owns and this package names no variable for; waiting for a place instead of being refused one, which `work-slots` owns; a cost per request other than one, a second cadence over a longer window, and any burst shape besides the one the counter this package ships implements; a cadence named per route inside the table rather than per wrap; headers reporting a budget on a request that was served, and any accounting a caller reads before it is refused; a clock of this package's own, a test naming a window short enough to pass in; a hard bound on how many keys the counter this package ships holds; logging a refusal, as in the four auth plans.
**Approach**: A rate wrap in `transport/http` (package `httpd`, root module, stdlib only) beside `RequireBearer` and `RequireRight`, built at wiring out of two things the service hands in: the function saying which caller a request belongs to, and the counter saying whether that caller has a call left and when it next will. Keying is the service's because every honest key is a project fact this repo's first rule keeps out, an address meaning a decision about which forwarded header to trust and a principal meaning a key only the service names; what it costs is that a request the function keys to nobody is served without a call being taken, so a route reachable with no credential and keyed on its principal is an unbounded flood by construction. The wrap sits on the handler, so the order a request meets is the table, then the bearer, then the right, then the rate, and no budget is touched for a request nobody routed; a service whose key is readable from the request alone places it outside the bearer wrap, the one position where a flood of unresolvable tokens is metered before its resolver is asked. The package ships the counter of a single process, built from a ceiling and a window, and a consumer running three replicas has three budgets until it hands in its own: the counter being a seam rather than a map fixed here is what keeps a shared store, its module and its dependency out of a decision that belongs to the service. Not a wrap in front of the table, which would meter and refuse a path nobody named, letting anyone spend a real caller's budget on 404s and answering 429 where `route-gate` exists to answer 404; and not a refusal a preflight can meet, which the placement on the handler settles by construction, the table answering a preflight before any wrap on a handler runs and a browser meeting a 429 there being as broken as by a 401.
**Threat surface**: input: nothing of the request is read here, the key coming from the function the service handed in and this wrap comparing no header and no address of its own; that key reaches a counter and never an answer, a header or a log, and the memory of the counter this package ships grows with the distinct keys seen inside two windows at most, an entry being forgotten by a sweep that runs at most once per window rather than at the instant that key's own window passed, so a caller rotating its key faster than the window drives that growth and a service needing a harder bound hands in a counter of its own. authn/authz: this grants nothing, identifies nobody and decides no caller's rights, which stay the bearer wrap's and the right wrap's; coverage is exactly the set of handlers wrapped, and the table's 404, its 405 and the preflight `Grant.Router` answers all land before any budget is touched, so what an anonymous caller learns of the table is what `route-gate` and `bearer-principal` left it and no flood of unrouted requests spends a real caller's budget; a key a caller can forge is a key with which it spends another caller's budget, which is why the keying function is the service's and why a service keying on a forwarded address trusts exactly its own proxy or meters that proxy as one caller. secrets: the refusal is one fixed body under one code, the same whatever key was metered, naming no key, no ceiling, no count and nothing of another caller, and the one number it carries is a retry delay about the caller's own bucket; an authenticated caller and an anonymous one are told that delay with the same precision, this package having nothing but an opaque key to tell two callers apart, so a ceiling is measured by probing and is not a secret; the counter's own error text reaches no answer and nothing here is written anywhere. egress: none, a key is counted and nobody is contacted, the calls a counter the service handed in makes being the service's own. dependencies: none added, the root module keeping its stdlib-only set.
**Landmarks**: transport/http/: package `httpd`, root module, stdlib only, where this lands, beside the `NewRouter` route table, the `RequireBearer` and `RequireRight` wraps a covered route carries, the `Grant` a browser meets, and the `WriteError` / `ErrorCode` failure envelope a refusal goes out through; authctx/: the key a principal rides under, read by a service's own keying function and untouched here; health/: the repo's other handler, served through no table and covered by nothing, out of scope; config/: how a service reads its environment at boot, this package naming no variable of its own; go.mod: the root module, nothing required outside the stdlib; README.md: one H2 per package, its shape and the reason behind it, the `transport/http` one carrying the table, the two wraps, the origin policy and the envelope.

## Steps
1. [transport] Refuse a caller past its cadence and tell it when to come back
   - seam: the handler the service serves, built at wiring with a counter the test provides, called over a served request from the package's external test
   - acceptance: a request whose caller the service's function keys and whose counter answers that a call is left reaches that route's handler; the same request whose counter answers that none is left is answered 429 in the package's failure envelope, under a machine-readable code of its own, carrying a retry delay of a whole number of seconds not below one, and that handler does not run; that refusal's body is identical for two callers, two keys and two delays, naming no key, no ceiling, no count and nothing of another caller; a request the service's function keys to nobody reaches the handler with the counter asked nothing; a request whose counter fails instead of answering is refused 500 under a code of its own, carries no retry delay, and that handler does not run either, a client telling the two refusals apart from the status and the code alone; a route of the same table this wrap does not cover is served with nothing counted; a request on a path nobody named is still answered 404 and a preflight that table answers is still answered 204, the counter being asked about neither

2. [transport] Meter a cadence the service named, inside the process serving it
   - seam: the same handler, built at wiring with the counter this package ships, over served requests from the package's external test
   - acceptance: a caller sending as many requests as the ceiling the service named is served every one of them and refused the next within that same window, its retry delay being no longer than that window; a second caller under a key of its own is served while the first is refused; the first is served again once that window has passed; requests sent concurrently under one key are served exactly the ceiling of them and refused the rest, under the race detector; a ceiling below one, and a window of zero or less, are refused at wiring under an error naming the value, and nothing is served
