# browser-origins
> a service lists at startup the origins whose browsers may read its answers, answers their preflight itself, and grants an origin nobody listed nothing at all

**Created**: 2026-09-22
**Out of scope**: where the list comes from, a service reading it from its own environment at boot, which `env-values` owns and this package names no variable for; a wildcard, a subdomain pattern, a regex or any origin matched otherwise than whole and exactly; the credentialed mode, so `Access-Control-Allow-Credentials`, a cookie sent cross-origin and `withCredentials`, which pairs with the wildcard this refuses; `Access-Control-Max-Age` and preflight caching; `Access-Control-Expose-Headers`, so a browser reads the body of an answer and the safelisted headers of it, not the `Allow` or `WWW-Authenticate` this package writes; a list named per route rather than per table; private network access; CSRF, which a same-origin policy does not solve and which a token in a header already sidesteps; logging a refused origin.
**Approach**: One origin policy named at wiring in `transport/http` (package `httpd`, root module, stdlib only), beside the route table, in two halves placed by what each one does: the grant is written in front of the table, where it answers nothing and only adds headers to whatever the table answers, so a listed origin reads the table's own 404 and 405 and the bearer's 401 as well as a handler's 200; the preflight is answered by the table itself, from the methods that table already names for the path, because it is an answer and not a header, so a preflight on a path nobody named is refused 404 like any other request and a covered route's preflight reaches no resolver. Not a wrap on the handler beside `RequireBearer`: the preflight carries no credential by construction, so inside or behind that wrap every preflight is a 401 and every browser breaks; and not an answer given in front of the table, which would answer `OPTIONS` for paths nobody named, the one thing `route-gate` exists to refuse. An origin nobody listed gets the answer it would have got with no grant header on it, never a status, a code or a body of its own: `Origin` is a browser's own statement about itself and anything that is not a browser forges it in one header, so refusing on it gates nobody, while a same-origin `POST` sends one too and would meet that refusal from the service's own page. It costs a non-browser caller every sign that its origin was not listed, an absent header being the whole verdict, and it leaves an operator debugging a mistyped list with no status and no code to go on, logging being out of scope here as in both auth plans.
**Threat surface**: input: the `Origin` header and the two preflight headers beside it, each attacker-controlled and each forgeable outside a browser, compared whole against a list fixed at wiring and never parsed, split, lowercased into a pattern or matched by suffix; nothing of a request whose origin is not on that list is read further, and the one thing echoed back is an origin that matched a listed entry exactly, never the list, never any other origin and never a header the service did not list. authn/authz: this grants a browser the read of an answer and decides nothing about who may call, which stays the route table's, the bearer wrap's and the right wrap's; a listed origin is granted that read over every answer this table gives, its refusals included, so listing an origin is trusting it with what a refusal says; the grant is one exact origin and never a wildcard, and the credentialed mode is refused with it, so no cookie of a viewer is ever granted; every answer whose headers depend on the origin carries `Vary: Origin`, without which a shared cache hands one origin's grant to the next caller, while the preflight's own answer depends on `Access-Control-Request-Method` besides the origin and names only `Origin` in that header, so a shared cache keyed on the origin alone can hand a stored preflight to a later bare `OPTIONS` on the same path, which costs a caller that is not a browser a wrong status and grants no origin anything the list did not grant it already; the preflight answers only for a path the table names and tells such a caller the methods that path names, which is the set its own 405 already carries to anyone, so what an anonymous caller can learn of the table is what `route-gate` and `bearer-principal` left it. secrets: no credential is read here and none is written; a refused origin is told nothing, the answer keeping the status, the code and the body it would have had, and nothing of any of this is logged. No egress: an origin is compared, never contacted. No dependency added, the root module keeping its stdlib-only set.
**Landmarks**: transport/http/: package `httpd`, root module, stdlib only, where this lands, beside the `NewRouter` route table, the `RequireBearer` and `RequireRight` wraps a covered route carries, and the `WriteError` / `ErrorCode` failure envelope a refusal goes out through; authctx/: the key a principal rides under, verifying nothing and naming no transport, untouched here; health/: the repo's other handler, served through no table and covered by nothing, out of scope; config/: how a service reads its environment at boot, this package naming no variable of its own; go.mod: the root module, nothing required outside the stdlib; README.md: one H2 per package, its shape and the reason behind it, the `transport/http` one carrying the table, the two wraps and the envelope.

## Steps
1. [transport] Grant the read of an answer to an origin the service listed
   - seam: the handler the service serves, built at wiring and called over a served request from the package's external test
   - acceptance: a request carrying an origin the service listed is answered exactly as it would have been without that header, plus a grant naming that one origin and nothing else of the list; a request carrying an origin nobody listed is answered with the same status, the same body and no grant header at all, as is one carrying no origin; an origin differing from a listed one by its scheme, its port or a trailing slash is one nobody listed, and no answer ever grants a wildcard; every answer of this handler carries `Vary: Origin`, granted or not; a listed origin's grant rides on the table's own 404 and on a covered route's 401 as it does on a handler's own answer, and no handler runs in either of those; a list carrying a wildcard, an empty entry, or an origin bearing a path, a query or no scheme is refused at wiring under an error naming that entry, and nothing is served

2. [transport] Answer the preflight of a path the table already names
   - seam: the same handler, built at wiring and called over a served request from the package's external test
   - acceptance: an `OPTIONS` request on a path the table names, carrying an origin the service listed and the method it means to send, is answered 204 with no body, naming exactly the methods the table names for that path and exactly the request headers the service listed; that path's handler does not run, and a route the bearer wrap covers answers that same preflight without its resolver being asked and without a 401; the same preflight carrying an origin nobody listed is answered 204 too, naming no method, no header and no origin; a preflight on a path nobody named is answered 404 in the failure envelope, naming no method; a preflight naming a method the table does not name for that path is answered that same list, which does not carry it, and no handler runs; an `OPTIONS` request carrying no preflight question is still refused 405 in the envelope, with an `Allow` header naming `OPTIONS` alongside the methods the service named, that path being one this now answers
